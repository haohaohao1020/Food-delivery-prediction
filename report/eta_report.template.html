    01

    业务目标与评估指标

    预测时点定在骑手接单瞬间，不是下单瞬间——接单那一刻才同时具备骑手负载、商家出餐压力与路况快照。

    目标变量：duration_min（分钟），从骑手接单到送达。预测时点 T0 = 接单时刻。T0 之后发生的一切（到店、等餐、骑行、进楼）都是待预测内容，不能进入特征。

    指标选择

    指标角色为什么是它
    MAE主指标业务损失以分钟线性计价（赔付、骑手奖惩、用户等待），且对长尾单不过度放大。3.4 分钟的误差可直接读成"平均每单多等或少等 3.4 分钟"。
    RMSE辅助惩罚大偏差，对应"极端误判"造成的客诉。RMSE 明显高于 MAE 就说明尾部有重罚单。
    MedAE辅助典型订单的表现，不被尾部拖拽。
    P90 绝对误差尾部运营关心"最差的那批单差多少"，6.9 分钟是当前兜底水位。
    MAPE可比只用于和行业口径对齐。分母在短单上过小，本报告仅在真实时长 > 5 分钟时计算。
    超时识别 F1 / AUC决策ETA 最终要驱动预警，必须单独评估分类侧，不能只看回归误差。
    P90 覆盖率校准承诺"90% 的订单不超过这个时间"。覆盖率偏离 90% 就是概率口径失效。

    不使用 MSE 作主目标：MSE 的梯度随误差放大，少数 90 分钟以上的异常单会绑架整个模型，而这些单在线上本就应走赔付而非预测。不使用 MAPE 作主目标：5 分钟的单差 3 分钟是 60%，3 分钟的单差 3 分钟是 100%，比例口径会把模型往短单上带偏。

    02

    数据清洗

    规则化、可审计、每条规则都留命中数。原则是能重算的修，不能重算的删，真实长尾不洗掉。

    规则命中动作说明

    几个关键判断

    • 缺失距离用经纬度重算，不是删行。重算值 = 球面直线 × 1.30 绕行系数。5609 条（8%）距离缺失若直接删，等于把"系统字段异常"这一类订单从训练集里剔除，模型学不到它们的真实时长。
    • 坐标越界不插补。经纬度颠倒、漂移出城市边界的订单（770 条），任何插补都会造出一批"假近单"，污染距离与片区特征。宁可删。
    • 天气按同日众数回填，再退到全局众数。天气是城市级变量，同日强相关，回填可信；不要按订单随机填。
    • 目标 ≤ 2 分钟或 > 180 分钟直接剔除。前者是系统时间戳错误，后者应走异常单 / 赔付流程。它们不属于"模型要预测的分布"，留着只会把误差指标做坏。
    • 加一条物理校验：平均速度 > 70 km/h 必删。外卖两轮车不可能达到，这类记录一定是距离或时间字段错位。这条规则在本数据集命中 0 条，但线上接入新城市时必须保留。
    清洗后画像：69,831 单，时长均值 32.3 分钟，P90 44.6，P99 62.8。分布右偏，均值被长单抬高，中位数更适合做"城市基准感"的沟通口径。
    03

    特征工程

    30 个特征，25 数值 + 5 类别。全部满足一条硬规则：T0 时刻在线上可获取。

    特征分组

    组特征业务含义
    基础distance_km, straight_km, detour_ratio, items, load, congestion_level, is_long_distance, has_rain距离、绕行、商品数、骑手当日负载、拥堵、远单标记。绕行系数 = 路网距离 / 直线距离，捕捉"看着近、实际绕"的片区。
    时间hour, weekday, is_weekend, minute_of_day, hour_sin/cos, weekday_sin/cos, peak_affinity, is_peak, is_late_night, day_of_month, is_month_start_week外卖需求是环绕 12:00 / 18:00 的钟形曲线，用 peak_affinity（到最近高峰的环形距离经 sigmoid 压缩）比整点 one-hot 平滑，避免 11:59 与 12:01 被判成两个世界。
    空间area_pickup, area_drop, same_area, pickup_lat/lon, drop_lat/lon取餐片区、送达片区（由坐标反查最近片区中心）、是否同片区。跨片区往往要过主干道或桥，方差更大。
    统计衍生area_hist_avg, area_period_hist_avg, supply_pressure片区、片区×时段的历史平均时长（截至昨天累计），以及前一日片区订单量 / 骑手负载得到的供需压力。

    类别编码

    • 时段 / 天气 / 商家类型 / 取送片区：LightGBM 直接用 category dtype，原生做类别分裂，不需要 one-hot。这样单列就能表达"雨 × 晚高峰"这类组合，而不会把特征空间炸开。
    • 不在树模型里做 one-hot：片区 8 类、时段 5 类，one-hot 后 30 维变 60+ 维，反而稀释分裂收益。
    • 线性回归 / MLP 对照模型才用 one-hot + 中位数填补 + 标准化，两条管线分开，互不干扰。
    • 不做高基数 ID 编码（商家 ID、骑手 ID）。它们会直接记住个体结果，是过拟合与泄露的高发区。要用商家维度，只允许用"截至昨天的商家历史均时长"这类聚合量。
    时间泄露风险点（逐条标注）

    高危 用当天全量统计（片区当天均时长、当天订单量）—— 包含本单与当日未来订单的结果。必须 as-of 到 T-1。本报告所有历史统计均按"累计到前一天"计算，测试集上仍保留这个约束。

    高危 用订单完成时间、骑手到店时间、取餐时间派生任何字段（如"等餐时长""骑行时长"）—— 这些是目标的可加分解，等价于直接给答案。

    高危 目标编码（target encoding）在全量数据上计算，而不是折内 / 时间片内计算。哪怕只算一次，也是把测试集信息带进训练。

    中危 "当日累计订单量"若统计整个自然日，就是未来信息；只能统计到当前分钟。

    中危 分箱边界、标准化参数、异常阈值在全量数据上拟合。本报告所有拟合类步骤只用训练段。

    中危 使用天气实况而非预报。线上 T0 只能拿到预报；离线若用实况，等于提前知道雨会不会下大。

    低危 用"骑手历史准时率"这类聚合特征时，若该聚合包含本单，仍属泄露。聚合窗口必须止于本单之前。

    为什么不是 CatBoost

    CatBoost 的 MAE 是 3.23，比选定的 LightGBM 低 0.14 分钟（约 4%）。这不是可以忽略的差距，但落地权衡如下：

    • 单调约束：LightGBM 有 monotone_constraints（advanced 方法），可以直接锁死"距离↑、拥堵↑、负载↑ 则时长不降"。CatBoost 的单调约束只能按特征全局声明，且与缺失/类别特征组合时限制更多。
    • 同一框架出 P50 与 P90：上调用的风险模型与 ETA 模型共用特征预处理、共用归因方式，运维面小一半。
    • 推理与部署：LightGBM 文本模型约 3 MB，热加载毫秒级；CatBoost 的类别处理带来更大的模型与更慢的单行推理，按峰值 QPS 估算成本更高。
    • 可解释：LightGBM 的 pred_contrib 直接给出分钟级 SHAP 贡献，运营工单可以直接展示"距离 +24.1 分、拥堵 +4.8 分"。

    结论：LightGBM + 单调约束上线，CatBoost 作为影子模型并行打分，连续 4 周线上 MAE 领先超过 0.2 分钟再考虑切换。

    XGBoost 与 DNN 的定位

    XGBoost 在这里偏弱（3.89）主要是 reg:absoluteerror 的二阶信息退化，收敛不如 L1/Huber 稳定；换 reg:squarederror 会改善 RMSE 但 MAE 未必。DNN（4.19）表现最差，符合预期：表格型特征、样本量 5 万级、类别基数小，树模型仍是更优归纳偏置。若未来接入骑手轨迹序列、商家出餐历史序列，DNN / 序列模型才值得重新评估。

    05

    数据集划分策略

    按天切分，段与段之间留隔离带。禁止随机打乱。

    60 天时间轴与切分

    培训 42 天 → 隔离 1 天 → 验证 8 天 → 隔离 1 天 → 测试 8 天。隔离带上的订单不参与任何训练、调参或校准。

    为什么必须时序切分

    • 外卖是同日强相关业务：同一天的天气、运力、大促、交通管制会同时影响当天所有订单。随机打乱会把同一天的订单同时放进训练与测试，模型等于提前知道了"今天全城偏慢"。
    • 实测差距：同一份合法特征，随机切分 MAE 2.59，时序切分 3.51。随机切分系统性低估 26%。
    • 随机切分还会让同一订单的重复/近重复记录跨集分布，进一步虚高效果。

    划分逻辑

    • 训练 2026-01-01 ~ 02-11：48,001 单，含跨年、工作日/周末、晴雨风。
    • 验证 02-13 ~ 02-20：9,664 单，用于早停、调参、P90 校准、风险阈值标定。
    • 测试 02-22 ~ 03-01：9,511 单，只评估，一次性使用。
    • 隔离带 1 天：防止边界处相邻日期的强相关（同一次冷空气过程、同一个大促周期）跨段渗透。当前统计窗口是"截至昨日的全历史累计"，1 天足够；若改成 7 日滑窗，隔离带必须同步改为 7 天。

    三层防泄露防线

    • 切分层：时序切分 + 隔离带 + 测试集只用一次。
    • 特征层：所有历史统计 as-of 到 T-1；线上特征快照按 PIT（point-in-time）join，拒绝读取当天分区。
    • 决策层：风险阈值与 P90 校准偏移只在验证集标定。任何在测试集上"微调一下阈值"的动作都是把测试集变成验证集。
    06

    训练策略与过拟合防范

    目标函数、正则、单调先验三层同时收口，最终早停在 389 轮。

    目标函数：Huber δ = 6

    LightGBM 的 monotone_constraints 不支持 regression_l1 与 quantile 目标。Huber 在 |误差| < δ 时梯度近似 MAE，超出后转为有界梯度，既保留 L1 的抗长尾特性，又能启用单调约束。δ = 6 分钟，约等于目标 P90 绝对误差的量级。

    核心超参

    learning_rate 0.03 · num_leaves 48
    min_data_in_leaf 120 · max_bin 255
    feature_fraction 0.82 · bagging 0.82/1
    lambda_l2 5.0 · early_stopping 120
    best_iteration 389

    单调约束：把业务先验写进模型

    对 distance_km, straight_km, detour_ratio, congestion_level, items, load, has_rain 施加 +1 约束：这些量增加时，预测时长不允许下降。收益有三层：

    • 可解释：运营问"为什么这单预估 70 分钟"，答案不会出现"因为距离更远反而更快"的反直觉结论。
    • 抗稀疏：极端组合（暴雨 + 远单 + 12 件商品）在训练集里样本极少，无约束模型可能给出荒谬的低估；单调先验把预测压回合理方向。测试集 MAE 只差 0.01 分钟，但尾部稳定性更好。
    • 可审计：模型行为可被业务方用一句话验证，不必依赖事后解释。

    过拟合防范

    手段做法针对的风险
    时序早停用验证段 120 轮无提升即停（最终 389 轮）训练集越跑越拟合当日噪声
    叶子样本下限min_data_in_leaf = 120单个骑手 / 单个商家被单独切成一片叶子
    行列采样feature_fraction / bagging_fraction = 0.82对少数强特征过依赖
    L2 正则lambda_l2 = 5.0叶子权重过大
    特征上限30 个特征，无 ID 类特征维度膨胀后记住个体
    单调先验7 个方向约束数据稀疏区的反直觉外推
    目标裁剪清洗阶段剔除 >180 分钟异常单主导损失

    调参方向（按收益排序）

    • 1. 特征 > 超参。当前增益最大的是 dist 之外的"等餐侧"信息：商家实时出餐时长、商家近 30 分钟单量、骑手当前在手单数。这三类特征上线后预计还能降 0.3~0.6 分钟。
    • 2. 目标函数与校准。P90 的原始覆盖率只有 81.7%，校准后到 90.3%。比调 num_leaves 更有价值。
    • 3. 超参搜索。Optuna TPE，200 次试验，搜索空间：learning_rate [0.015, 0.06]（对数）、num_leaves [24, 96]、min_data_in_leaf [60, 400]、feature_fraction [0.6, 0.95]、lambda_l2 [1, 30]、max_bin [127, 511]。用验证段 MAE 作目标，不做交叉验证（会破坏时序性）。
    • 4. 分群建模。远单（> 6 km）与近单的时长机制不同，可试"单模型 + 距离交互特征"先，再评估分群模型是否值得增加维护成本。
    07

    上线推理、阈值与失效场景

    离线误差只是入场券，线上要解决的是特征一致性、概率校准与坏日子。

    推理链路

    • 特征一致性：离线与线上共用同一份特征变换代码（build_features 的线上版 build_live_row），任何一侧改动都要走同一套单测。离线用 pandas 整表聚合，线上读天级快照，二者必须能对上同一行。
    • PIT join：特征快照表带 stat_date，读取时强制 stat_date < order_date。这行断言是防线上穿越的最后一道闸，必须写死在特征读取层，而不是指望调用方自觉。
    • 打分输出：P50（用户端 ETA）+ P90（运营风险）+ 归因（minute 级 SHAP）。P90 与 P50 若出现交叉（分位模型独立训练），取 max(P90, P50)。
    • 性能：LightGBM 文本模型 3 MB，单行推理 < 1 ms，批量 1000 行约 8 ms。服务启动预热一次，常驻内存。
    • 降级：模型不可用或关键特征缺失 > 2 个 → 退到规则公式（距离 / 18 km/h + 12 分钟）→ 再退到"城市 × 时段"均值表。降级必须打点，否则线上误差升了没人知道。

    业务阈值

    阈值取值口径
    超时线 SLA45 分钟城市级赔付与考核口径，可按片区/品类配置。
    P90 预警线验证集 F1 最优得到，测试集 P90 > 该值则打标推运营。
    P90 校准偏移 δ验证集逐日 P90 残差的 P90，加到分位模型输出上。取最大日会被单个极端日带偏，故取分位。
    ETA 展示下限18 分钟低于此值用户不信，且末端交付有物理下限。展示层裁剪，不影响模型输出。
    模型重训每周滚动最近 60 天。影子模型先跑 3 天再切。

    逐日 P90 覆盖率：坏日子藏不住

    整体覆盖率 90.3% 达标，但按天拆开后，测试段最差的一天只有 76%。这正是线上必须按天监控的原因——只看整体，会把系统性漂移读成"偶发波动"。

    测试段逐日 P90 覆盖率

    虚线为名义 90%。低于 85% 的两天均对应雨 + 晚高峰叠加。

    典型失效 case

    场景表现处理
    极端天气 / 大促全城时长整体上移 15~30%，模型按特征给不出这个整体抬升，P90 覆盖率掉到 76%按天滚动校准 δ；触发"城市异常日"开关，整体乘系数并人工复核
    新片区冷启动无历史统计，area_hist_avg 为空，预测退回全局均值，方差大片区上线前先跑 2 周影子积累统计；空值走"城市均值 × 片区难度系数"兜底
    单商家爆单 / 出餐故障等餐时长暴涨但特征里只有商家类型，严重低估接入商家实时出餐时长与近 30 分钟单量；商家异常时给片区级加成
    骑手挂多单同送骑手在手单数增加导致绕行，当前只有"当日已接单量"，粒度太粗补"骑手当前在手单数""同向合并单数"特征
    地址 / POI 错误末端交付时间从 2 分钟涨到 10 分钟，任何特征都看不出来识别"历史投诉地址""定位漂移"，走末端时长上浮规则
    跨江 / 跨桥订单直线距离近但只有固定桥可过，绕行系数低估用路网距离替代球面距离；路网不可得时按片区对历史绕行系数
    时间戳错乱接单时间晚于送达时间，或时区错推理入口做单调性校验，异常单直接降级到规则

    业务可解释：高风险订单怎么排查

    每单输出 P50 / P90 与前三项驱动因素（分钟级贡献）。运营看到的不再是一个数字，而是可核对的分解。

    样例取自测试集 P90 最高的订单。归因为 LightGBM pred_contrib，单位分钟，正数表示把预测推高。

    # ---------- 特征：所有历史统计严格 as-of 到前一天 ----------
daily = (f.groupby(["order_date", "area_pickup"])["duration_min"]
          .agg(["sum", "count"]).reset_index()
          .sort_values(["area_pickup", "order_date"]))
g = daily.groupby("area_pickup", sort=False)
# cumsum 包含当天，减掉当天 → 得到"截至昨天"的累计量
daily["hist_sum"] = g["sum"].cumsum() - daily["sum"]
daily["hist_cnt"] = g["count"].cumsum() - daily["count"]
daily["area_hist_avg"] = np.where(
    daily["hist_cnt"] >= 30, daily["hist_sum"] / daily["hist_cnt"], np.nan)

# ---------- 时序切分：按天切 + 隔离带 ----------
d = df["order_date"].dt.normalize()
train_end   = d.min() + pd.Timedelta(days=train_days - 1)
valid_start = train_end + pd.Timedelta(days=1 + embargo_days)
valid_end   = valid_start + pd.Timedelta(days=valid_days - 1)
test_start  = valid_end + pd.Timedelta(days=1 + embargo_days)
tr, va, te = df[d <= train_end], df[(d >= valid_start) & (d <= valid_end)], df[d >= test_start]

# ---------- 训练：Huber + 单调约束 + 时序早停 ----------
p = dict(objective="huber", alpha=6.0, metric="mae", learning_rate=0.03,
         num_leaves=48, min_data_in_leaf=120, feature_fraction=0.82,
         bagging_fraction=0.82, bagging_freq=1, lambda_l2=5.0, seed=42)
# 距离/拥堵/商品数/负载/绕行/雨 → 预测时长不得下降
p["monotone_constraints"] = [MONOTONE.get(c, 0) for c in X_tr.columns]
p["monotone_constraints_method"] = "advanced"
model = lgb.train(p, lgb.Dataset(X_tr, y_tr), num_boost_round=2500,
                  valid_sets=[lgb.Dataset(X_va, y_va)],
                  callbacks=[lgb.early_stopping(120, verbose=False)])
